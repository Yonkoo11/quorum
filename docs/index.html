Quorum

A local Solidity scanner. Six lenses, no messages between them. A finding publishes only when two of them reach it from different evidence.

Source Demo Claim on Base Sibyl Memory

Nothing publishes until two lenses agree.

Each pair works from different evidence. For reentrancy, callorder-lens sees an external call before a state write; guard-lens sees value leave with no reentrancy guard. One of those is a candidate. Both is a finding.

The count of who agreed lives in memory, not in any lens. Turn memory off and the same six programs still see the bugs. They never learn the other one did, so nothing is reported.

On Aerodrome’s Router, WETH9 and a Compound proxy it confirms nothing and files eleven candidates. That is the intended behaviour.

What memory is for

  • Agents scan the same unit twice claim_work
  • Two lenses can never agree record_sighting
  • A confirmed idiom is forgotten promote
  • A human retirement does not stick retire

All of that is quorum/memory.py.

The finding never leaves the machine. The chain only gets a digest.

1,000 QUORUM to publish. Scanning is free.

Each claim burns the fee on Robinhood Chain, then writes the digest to Base with that burn’s hash. No burn, or a burn from a different wallet, and verify fails.

A paid claim can be revealed. Another swarm can import it. Unpaid patterns never enter anyone's memory.

run, recall and --no-memory never touch the token.

Run it locally

Python 3.10–3.13. MIT. Nothing is uploaded. Fetching verified Base source does not need an API key.

git clone https://github.com/Yonkoo11/quorum && cd quorum
python3 -m venv .venv && .venv/bin/pip install -e .

.venv/bin/quorum run --targets fixtures/*.sol
.venv/bin/quorum run --no-memory
.venv/bin/python -m pytest tests -q             # 16 tests

fetch, swarm, recall, retire, attest, verify, reveal, import. Attest needs BASE_RPC and DEPLOYER_PRIVATE_KEY.
